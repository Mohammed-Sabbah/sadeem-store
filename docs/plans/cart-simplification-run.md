# سجل تبسيط السلة

التاريخ: 2026-11-13. الأساس: 41c5510. إذن التنفيذ صدر صراحة بعد مراجعة المسودة.

## خطوات العمل

- [x] قراءة Principles من poteto-mode وتثبيت القيود والبيانات.
- [x] Ground: فلو الضيف محلي، والحساب على السيرفر، والشراء داخل معاملة موجودة.
- [x] Sketch: مراجعة أصلية إلزامية للدمج والتعديلات، دون سجل إيصالات بديل.
- [x] Agree: وافق المستخدم على فقد اختيارات الضيف بعد الحذف عند فشل المحاولة.
- [x] Implement: تعديل الحساب والضيف ثم إزالة الكود القديم واختبار كل مرحلة.
- [x] Verify: مراجعة مستقلة وفحوص API وMongoDB والمتصفح.
- [x] Commit: كوميتات محددة للمهمة فقط دون push أو حذف بيانات تاريخية.

## نقطة تنظيم العمل

- **Blocking first steps.** تثبيت المواصفة وعقد مراجعة الدمج وإثبات السلوك المعيب قبل تعديله. التحقق من اتصال قاعدة الاختبار قبل الاعتماد على نتائج المعاملات.
- **Independent workstreams.** منفذ واحد يملك الباك والواجهة والاختبارات المترابطة؛ المنسق يملك فحص المتصفح والتوثيق. المراجع يقرأ ولا يكتب.
- **Shared mutable state.** لا تحرير متوازٍ لنفس الملفات. سلة الحساب تتغير بشرط مراجعة ذري، وأخذ مصدر الضيف وحذفه يتمان بتنسيق التبويبات.
- **Smallest safe decomposition.** صاحب تنفيذ واحد يمنع اختلاف العقد بين الباك والفرونت. تتبعه مراجعات مستقلة محددة النطاق.

## قرارات وحدود

البيانات هي سلة حساب بمراجعة وعناصر، ومحاولة ضيف في الذاكرة تحمل نفس المراجعة. لا إيصالات جديدة ولا حزم استرجاع جديدة. يبقى الحفظ المالي وملكية الحساب كما هما. البيانات القديمة الموجودة لا تُحذف ولا تُرسل تلقائيًا.

مهارات Cursor الفرعية غير المثبتة وأداة Skill غير المتاحة لا تُستدعى صوريًا. نستخدم ملفات المهارات المتاحة، واختبارات تفشل ثم تنجح، وأدوات Codex الفعلية. لا يدّعي السجل تطبيق مبدأ له ملف فرعي لم يُقرأ.

## دليل التنفيذ والتحقق

- الباك إند انتقل إلى كتابة مشروطة بمراجعة العميل الأصلية، للتعديلات والدمج. أُزيل نموذج CartReceipt واستخدامه، ولم تُحذف المجموعة التاريخية.
- اختبارات الباك الجديدة فشلت على السلوك القديم، ثم نجح 23 اختبارًا بعد التعديل. أعاد المراجع المستقل تشغيلها على MongoDB معزولة ونجحت.
- مراجعة الباك المستقلة لم تجد مشكلة مانعة. كود معاملة الشراء لم يتغير.
- سُجل الباك في الكوميت 7c9781f، وبقيت تعديلات المستخدم في الواجهة خارجه.
- فحص المتصفح الجديد يشترط حذف مصدر الضيف قبل الطلب ومراجعة أصلية، ويشمل فشل الإرسال وضياع رد النجاح وعدم إعادة الدمج بعد reload. التشغيل أثناء تعديل الوحدات رصد أخطاء تجميع مؤقتة؛ لا يُحسب تحققًا نهائيًا حتى يُعاد على المصدر المستقر.
- كشفت مراجعتا المواصفات والجودة أن تبويب ضيف قديم يستطيع إعادة حفظ الكمية التي نقلها تبويب آخر. اختبار الحالة فشل بقيمة 3 بدل 1 قبل الإصلاح، ثم نجح. كتابة الضيف الآن تقرأ التخزين الحالي وتعدله تحت نفس قفل أخذ المصدر؛ تغيير كمية مطلقة من شاشة قديمة يُرفض مع تحديث السلة بدل إحياء الكميات المنقولة.
- نجحت المجموعة الكاملة للواجهة: 63 اختبارًا. تضم فحوص الضيف والحساب والرد المفقود والتبويبات والتخزين القديم وصفات الخيارات. نجحت فحوص الباك الـ23 على قاعدة MongoDB معزولة؛ كود الدفع والطلبات لم يتغير.
- نجح بناء الإنتاج وفحص TypeScript. فشل بناء أول داخل العزل بإنشاء عملية PostCSS والاتصال بها؛ أعيد خارج العزل ونجح على المصدر النهائي.
- نجح lint على Context وملفات cart الجديدة والمعدلة وصفحة السلة، دون أخطاء، مع تحذير img سابق واحد.
- نجح Chromium على نسخة الإنتاج الفعلية باستخدام API تجريبية. شمل الحذف قبل الإرسال، ورفض المراجعة القديمة، وأخذ المصدر من تبويبين، وتعديل تبويب ضيف قديم بعد النقل، وفشل النقل دون إعادة محاولة، وضياع رد نجاح ثم تحديث الحساب، وبقاء البيانات القديمة، وصفات الخيار، والخروج. أخطاء أدوات المحاكاة والتجميع المؤقتة لم تُعد نجاحًا؛ النتيجة النهائية اجتازت كل التأكيدات دون استثناءات متصفح.
- لا حذف لمجموعة MongoDB التاريخية ولا لمفاتيح الحساب أو الحزم القديمة. لا إيصالات جديدة أو سجل بديل داخل Cart. إذا كانت نسخة ضيف مرتبطة بمصدر قديم معلق، تُرفض الكتابة فوقها بتنبيه بدل طمس بياناتها.
- لم تُدعَ مهارات أو أدوات غير متاحة، ولم تُحذف شروط اختبار لتجاوز عيب؛ اختبارات نجاح replay القديمة استُبدلت بتوقع التعارض وفق السياسة الجديدة، مع الإبقاء على فحص الكمية النهائية.
- سُجل فلو الواجهة والاختبارات النهائية في الكوميت b9852b1. بقيت ملفات CSS/layout/home وتعديل لون ProductCard السابق خارج كوميتات المهمة.
